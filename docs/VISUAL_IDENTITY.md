# M1 Addendum — Zero Sum Visual Identity

Owner-approved direction, received 2026-11-05. This records intended experience; no composed application or aesthetic acceptance is claimed.

The entire Zero Sum experience, including navigation, interface, decision screens, typography, transitions, and eventual portal, must share the visual language of the story.

**Approved direction:** Classic 1980s–1990s-inspired cel-anime characters in painterly cinematic environments, accompanied by a cohesive retro-futuristic anime interface.

## Requirements

1. Do not use a generic dashboard, conventional SaaS design system, or unrelated modern website theme.
2. Create an original interface that feels native to Zero Sum's cyberpunk anime universe.
3. Use cinematic compositions, restrained tactical UI motifs, distinctive typography, and a consistent color palette.
4. Make narrative illustrations the visual centerpiece; interface elements should support rather than compete with them.
5. Present decisions as meaningful dramatic moments, not ordinary website navigation.
6. Apply the same visual identity to the entry screen, language controls, narrative presentation, choices, endings, and replay.
7. Preserve readability, accessibility, bilingual support, responsive behavior, and reduced-motion compatibility.
8. Use lightweight CSS and existing assets where practical. Do not introduce an expensive or unfamiliar visual-production pipeline.

## Verification and acceptance

Provide representative desktop and mobile screenshots of the opening/title screen, narrative scene, decision interface, and ending screen. Evaluate the entire composed experience against the approved anime direction, not merely the individual illustrations.

The application must feel like an interactive work belonging to Zero Sum's fictional universe—not a generic website displaying anime images. Automated test success is insufficient evidence of visual acceptance. Final aesthetic approval remains with the owner.

The eventual portal shares this direction, but portal changes remain outside M1 authorization. See [M1 brief](M1_BRIEF.md) for implementation scope and exclusions.
